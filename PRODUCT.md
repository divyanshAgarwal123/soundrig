# SoundRig
SoundRig is a local browser-game sound authoring prototype for indie developers, especially small JavaScript/Phaser projects. A developer brings short recordings, configures responsive playback, captures representative runs, keeps separately declared expectations, and delivers reusable sound assets or a live component.

The core workflow is: load/import → choose playback quality → audition/play/capture → run saved checks → optionally request a guarded Meta edit → save/reopen → export → consume independently. Muse Glimmer edits a bounded recipe; code validates supported behavior and locked layers. It does not generate recordings or music. Model access is optional for saved/manual workflows and absent during gameplay.

Schema1 retains classic output. Schema2 saves an explicit classic/studio selection. Studio adds ratio-dependent band-limited sample playback and an exactly linear quiet-signal output region. This is signal engineering, not evidence of a preferred sound.

The standard cue kit includes11static cues, sprite markers, project/source declarations, pinned Phaser consumer and typography/licenses. The live workflow retains dynamic controls/wind/cadence and an offline verifier. Portability means ordinary WAV files and the tested JavaScript/Phaser paths; automatic other-engine imports are not implemented.

This product should earn repeat use while developers iterate on sound behavior and check regressions. There is no measured outside adoption, developer time saving or listening preference. The simplest alternative is ordinary sound-pack files plus Phaser playback; SoundRig's hypothesized value is keeping editable behavior, representative inputs, expectations and deliverable output together.

The approved visual direction is Soundcheck pressing room: cream, orange, ink, oversized sleeve typography and dimensional vinyl. Landing is Persuade, studio Operate, guide Read. Reference comp and development-only contract are outside served product content. Generated record imagery is a metaphor. All shipping controls/text remain native accessible UI. Phones/tablets prioritize audio controls before artwork; wide desktop retains record entering from the right.
