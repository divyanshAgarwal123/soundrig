User request: research ways to make SoundRig substantially more useful, implement and test them, then rescore. Current project/ at8771 is the working surface. Its previous source/runnable ZIPs are immutable rollback artifacts in output/. Root is sole writer. No publication, outreach or submission authorized here.

## Research and decision

Primary sources checked November4,2026 IST:

- Phaser audio: https://docs.phaser.io/phaser/concepts/audio — playback, rates, volume, markers and spatial audio are established.
- Phaser events: https://docs.phaser.io/phaser/concepts/events — explicit events, listener identity and lifecycle cleanup; no arbitrary project understanding.
- Phaser3.90 emitter API: https://docs.phaser.io/api-documentation/3.90.0/class/events-eventemitter . Runtime stays pinned3.90; current guides also describe newer versions.
- Phaser's official audio skill: https://github.com/phaserjs/phaser/blob/master/skills/audio-and-sound/SKILL.md — sounds need explicit scene-shutdown cleanup; this is an integration concern, not a new audio invention.
- FMOD: https://www.fmod.com/studio and https://www.fmod.com/docs/unity/user-guide.html — live iteration and recorded-session profiling already exist. SoundRig cannot claim these as novel or imply professional-middleware parity.
- Godot: https://docs.godotengine.org/en/stable/tutorials/audio/audio_streams.html — randomization/positional playback already exist; native integration would require separate executed coverage.
- Meta: https://dev.meta.ai/events/global-hackathon — indie creativity, technical ambition and working behavior; Build for Your World. Public deadlineNov4 9pmET. Organizer guide weights Impact30/Meta25/Execution20/Demo25 were refreshed in the rendered guide before final scoring.

Three routes: A larger catalog/music support adds content without solving integration; B reusable game wiring + saved multi-run audio contracts + guarded Meta iteration solves a repeat task and is chosen; C broad Unity/Godot integration and automatic project import is too large to validate in this phase. These are product hypotheses from documented workflows, not interviews or demand evidence.

## Outcome / done when

1. A framework-neutral adapter maps explicitly configured raw numeric/boolean fields and named game-event aliases to the four controls/three events. It normalizes once for live player and recorder, deduplicates unchanged states, retains equal-time ordering, refuses invalid mappings/values/unknown aliases, and exposes invalid/overflow capture rather than truncating. No generated code or inferred collision rules. A Phaser helper owns only its own listeners, disposes on shutdown/destroy and stops on pause/sleep. A stopped/paused capture is invalid; enable audio by gesture again, rather than claiming a trace represents dropped stop commands. Bridge does not inherit Phaser global mute/volume implicitly.
2. Developers retain several named recorded runs as a bounded contract: at most6 cases,30s combined,32KiB compact JSON. Each validated trace has explicit event-count, rendered cue RMS, silence-window and headroom limits as configured. Report exact project/module/trace identities, per-case failures and coverage. Cue RMS is a signal-level metric, not perceived audibility or preference. Negative controls must fail: muted pickup, overloaded mix, wrong event mapping, missing coverage, invalid traces. Render through the actual project-specific bank/mix.
3. Existing Meta patch flow can receive the contract. Validate contract before inference; candidate must pass all runs after ordinary schema/behavior checks before application. Preserve locks and active rig on failure. Keep at most2 model attempts and15s validator timeout; failed semantic checks can feed deterministic measured errors into one repair, infrastructure errors do not spend another call. Execute one successful fresh edit and one impossible/contradictory guard rejection, retaining raw records and measured results.
4. Workflow ZIP includes component, adapter, bindings, editable project, contract/traces, independent runner, licenses and a dependency-free Node verifier. Actual downloaded/extracted artifact runs `node verify.mjs` without authoring/model and reports nonzero exit on a failing control. Browser integrate reusable adapter in the existing credited Phaser game and the separate JS runner; capture, save contract, Meta edit, export, replay and validate. Label real captures versus synthetic controls. Preserve old saved projects/exports and12-suite regressions.

## Bounds and verification

Observed browser refinement: normalize controls to four decimal places (absolute quantization error at most0.00005) before forwarding to both player and recorder. This suppresses tiny physics float jitter, rather than silently dropping recorded updates. The fixed SDK precision is explicit; it does not claim raw-control losslessness. Lossless compaction of already-normalized saved traces remains separately tested. Restart cleanup retains the original physics-world object because Phaser clears scene.physics.world before later shutdown listeners.

Council specification clarifications before build: expected event counts come from a developer's declared scenario/game outcome counters, not from mapped/recorded events. A wrong shared alias must fail that independent count oracle. The UI requires explicit expected land/pickup/hurt counts for adding a run; imported/synthetic cases are labeled as declared, not independently certified captures. Reports include exact mapping/capture provenance when available. Playback/recording sharing one adapter proves consistency, not that mapping intent was correct. Capture invalidates on AudioContext suspension/closure, Phaser pause/sleep/shutdown or command overflow; no stale timer may publish it afterward. Suspended audio requires another user gesture. Check before each forwarded input and observe the started context's statechange; remove owned listener on disposal. RMS is linear full-scale signal RMS in the first250ms after each positive event, clipped at trace end; overlapping same-event tails remain included. Silence checks include all tails in their stated windows. These are explicit arithmetic contracts, not masking/perceptual scores. Serialization sorts keys for identity. Keep old recorder API working; new adapter owns its own capture lifecycle.

Further performance/oracle clarifications: one project-module import per candidate, shared across sequential cases; no new browser runtime import for checks/Meta edits. Validate at48kHz,128-frame blocks, seed17. Whole validation subprocess (generic plus contract) retains its15s deadline. Contract traces obey existing1200-command/10s caps, total30s; at most3 event metrics per case and4 silence windows per case. Cue metrics render only layers for the named event; they exclude other events/background, retain same-event overlaps, and never claim a linear decomposition of the nonlinear mixed bus. Use explicit numeric tolerances1e-9 for threshold comparisons; exported parity on the tested runtime is exact Float32, not a cross-engine guarantee. Release each case PCM before the next. Measure worst permitted contract with maximum bank/voices; include cold process wall time and memory, not only DSP averages. Independently calculated constant-wave RMS/event-count expectations and silent/overload/wrong-map mutations are required, since shared-runtime agreement does not prove numerical intent. One-run mode remains supported and is the simpler baseline; several runs are optional until distinct scenarios matter.

Relay: one read-only seam explorer, root implementation, fresh functional falsifier. Existing editor visual system retained; add one native disclosure and clear pass/fail results, no rebrand. Keep previous audio engine/schema/sample limits, immutable bank staging and module-import caps. No music/voice generation, new engine port, external user study, hidden auto-upload, production/deployment or preference claim. Planned2–4hours plus evidence packaging; cut optional polish rather than gates.

Verification: unit/integration tests for mapping, capture/lifecycle, strict contracts and meaningful negative controls; authoring contract/recovery tests; exported offline verifier and module parity; actual CUA browser eventful runs and independent downloaded pack with authoring disabled; desktop/mobile review and reproducible source archive. Higher rating is not a completion gate. External adoption, listening preference and human time savings remain unknown.
