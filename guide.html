First sound, without inference.

  1. Open the studio and press Load working example. It includes two actual Kenney CC0 imports and saved Meta edits. Cues, Recordings, Revisions, Meta edit and Delivery separate the working tools.
  2. Enable audio. Play Pressing Room Run with arrow keys, A / D and Space, or the on-screen movement controls. Collect eight masters and avoid the rolling press. Capture six seconds or replay a saved scenario. Pause and restart stay beside the game.
  3. Replace a sound slot with a PCM16 WAV and a source/license note. Preparation and a muted audio-thread check complete before replacement.
  4. Save the editable project to keep the original WAV, source declarations, recipe, mix and quality mode.
Open the working example

Imports: mono/stereo PCM16 WAV, 24/44.1/48 kHz, 4 ms–1.5 s, at most 400KiB per file. Eight fixed sound slots. MP3, OGG, voice and music generation are not supported in the importer.

Choose how the kit plays.

Classic preserves earlier SoundRig rendering. Studio uses a 24-tap, 64-phase band-limited sampler with cutoff adjusted for playback ratio. Quiet signals remain linear through 0.8; larger peaks meet a bounded soft knee. Source recordings, recipes and sample-rate metadata are retained.

Studio costs more processing. It passed known-tone spectral/transfer tests and the local maximum validator workload; this does not establish listener preference or performance on every device. Playback remains mono with short effects. The source recording is still the strongest limit on sound quality.

Cue focus briefly lowers continuous layers around pickups and damage. Headroom correction applies to the selected trace, not every possible play session. You can compare the same inputs at matched RMS; RMS matching is not perceptual loudness matching.

Keep the runs that matter.

Load the tested checks or capture your own scenario. Enter expected landing, pickup and damage counts from gameplay outcomes, independently of the audio mapping. Save the checks JSON alongside the project.

With protection enabled, Meta must pass the saved scenarios before its edit is applied. The checks can detect missing event mappings, unwanted sound in a declared window, insufficient cue level and excess mix level. They cannot judge style, emotion or perceptual masking.

At most 6 cases, 30 seconds combined and 32 KiB compact definitions. Each trace is at most 10 seconds and 1200 commands. Interrupted or overflowing captures retain the prior trace instead of publishing a partial success.

Fresh authoring in this local prototype requires separately installed Ollama and muse-glimmer:30b-mlx, roughly 19 GB of weights. The latest earlier guarded tests took 38.326 seconds for an accepted intent and 73.658 seconds for two rejected candidates. Saved examples, manual editing, replay and export need no model.

Hear a recording before replacing it.

In the Recordings tab, choose a sound slot, a PCM16 WAV and its source note. Preview this recording prepares one candidate while your current sound stays in place. Hear original and Hear prepared use whole-clip RMS matching with a shared peak ceiling; the original comparison is averaged to mono. The duration, removed padding, preparation gain and source warnings explain the change. This is not a listening score or the actual game mix.

Use this recording applies it only after enabled saved checks pass. Discard removes the preview. The original WAV remains in your editable project. Source clipping and background noise are not repaired. In the Cues tab under Set the cue, exact level and pitch changes can pass your saved checks before application; Undo restores the previous cue edit within the same sound revision. Hear current cue auditions the actual mix level.

Return to a version that worked.

In Revisions, name the current kit and save a checkpoint. Inspect shows the exact sound, settings, selected run and check-definition differences. Restore saves a recovery checkpoint before replacing your current work. Enabled current checks must pass and stay in place; with protection off, the saved definitions and protection setting return instead. Restored checks are always UNCHECKED: rerun them and re-export afterward. Live game position is not saved.

Checkpoints survive reloads and server restarts on this computer. Download a revision for a portable backup. Import adds it to history without changing the active kit. History holds 24 checkpoints and 48 MiB of snapshot data; database and temporary files use extra space. Full history refuses saves and restores until you download and remove a checkpoint. Nothing is deleted automatically. This is explicit saving, not autosave or cloud sync. The private history is excluded from the source ZIP; keep it when updating the app.

Deliver the version your game needs.

Static game-ready WAV kit

Export the current kit to 11 cues: three takes each for landing, pickup and damage, plus two isolated full-speed footsteps. Takes use the recipe's variation and can match if none is authored. You also get a single WAV sprite, Phaser markers, editable project, source notes and a separate pinned Phaser 3.90 test scene.

  1. Download and extract the game-ready WAV kit.
  2. Inside that extracted folder, serve the files:
    python3 -m http.server 8782 --bind 127.0.0.1
  3. Open http://127.0.0.1:8782/.
  4. Select a cue and press Play cue. The independent scene loads the delivered sprite.

Phaser setup in your own scene:

// preload
this.load.audioSprite('kit', 'sprite.json', ['sprite.wav']);
// after a player click/tap, in the appropriate game event
this.sound.playAudioSprite('kit', 'pickup_01');

In the Delivery tab, choose Godot in the WAV kit destination to add a native adapter and test scene. Extract the ZIP, open project.godot, and run the scene. For your own game, copy soundrig.gd, manifest.json and audio/ together. Follow GODOT_README.md; call kit.play_cue("pickup") from your game’s pickup event. Keep that call when replacing the kit on the next revision. The adapter verifies WAV hashes and bounds overlapping voices; it does not infer game events. Tested with Godot 4.7.2.

For other engines, import the WAV files and wire the events yourself. Static files do not reproduce dynamic wind, cadence, changing control mappings or live ducking. Those remain in the live component. Saved JavaScript gameplay checks do not verify another engine’s gameplay.

Live component and gameplay checks

Export integration + checks retains the dynamic component, explicit raw-state adapter, saved scenarios and a Node verifier. It needs neither the authoring server nor a model after export.

node verify.mjs

Exit 0 passes; 1 is a failed signal/count check; 2 means invalid or stale inputs. After changing sounds, recipe, mix, quality or bindings in SoundRig, re-export. The exported project JSON alone cannot change the already-built component.

Local files. Clear boundaries.

The development server binds to this computer's loopback address. Imported sounds and local Meta requests stay on this computer. The server retains authoring journals as local evidence; the redesigned server does not serve those journals as website files. A result receipt can be saved from the studio.

Exported projects include original WAV data and source/license notes. Review them before sharing. A user source declaration is preserved, not ownership-verified. Supplied Kenney recordings have separately known CC0 provenance.

This is an indie browser-game prototype, not a professional DAW or universal engine importer. No outside developer adoption, comparative time saving, listening study or production reliability is claimed. The site uses generated record artwork as a visual metaphor, not a photograph of a real SoundRig product.
